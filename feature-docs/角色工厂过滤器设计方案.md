# 仪表盘角色工厂过滤器设计方案

> 版本：v1.0  
> 日期：2026-06-24  
> 状态：待确认

---

## 一、背景

仪表盘中有"工厂"过滤条件。不同的用户应该看到不同工厂的数据——普通销售员只看自己工厂的数据，管理层可以看多个工厂的数据。

同时，客户对**首次打开仪表盘的查询速度**有较高要求，因此引入了**预热机制**：系统在用户访问之前，提前把常用查询的结果缓存好，用户打开时直接读缓存，无需等待数据库查询。

---

## 二、两个独立问题

这个需求本质上涉及两个独立的问题，需要分别处理：

| 问题 | 说明 |
|------|------|
| **数据权限（正确性）** | 用户能看到哪些工厂的数据？ |
| **预热缓存（性能）** | 用户首次打开时，查询结果已在缓存中 |

**两者的交叉点**：缓存的 key 由查询条件生成，而查询条件受用户的数据权限决定。因此，要让预热缓存命中，必须让"用户的实际查询条件"与"已预热的查询条件"完全一致。

---

## 三、配置方式

在仪表盘的过滤器设置中，新增"**角色工厂配置**"：

```
角色工厂配置示例:
  惠州厂销售  →  惠州厂
  明阳厂销售  →  明阳厂
  南宁厂销售  →  南宁厂
  ...
  总经理角色  →  [惠州厂, 明阳厂, 南宁厂, ...]（多工厂，仅多选过滤器适用）

过滤器默认值（兜底）:
  未匹配到任何角色的用户，使用此默认值
```

> 注意：以上配置在每个仪表盘中**独立维护**，同一个角色在不同仪表盘可以有不同的工厂配置。
>
> 仪表盘另有"管理协作者"功能（配置角色对仪表盘的访问权限：可阅读/可编辑/可管理），与此处的"角色工厂配置"**相互独立、作用不同**：
> - **管理协作者**：控制角色能否打开/编辑该仪表盘（访问权限）
> - **角色工厂配置**：控制角色打开后看到哪个工厂的数据（数据过滤）
>
> 同一个角色可能同时出现在两处，各自配置各自的内容，不冲突。

---

## 四、前提条件

要让方案正常运作，以下条件**必须同时满足**：

### 前提1：每个角色在配置中只映射固定的工厂

每个角色应映射到一个明确的工厂集合（单个或多个），且该集合对应一个**独立的预热任务**。

### 前提2：显式配置角色工厂，才能保证该角色的初始加载命中预热

系统的工作原则：**配置了即预热，未配置走默认值**。

| 角色是否在"角色工厂配置"中有条目 | 初始加载行为 |
|---|---|
| 有配置 | 按配置的工厂查询，命中对应预热缓存，速度快 |
| 无配置 | 走"过滤器默认值"，命中默认值预热缓存，速度也正常 |

因此，**不需要为每个角色都添加配置**，只有需要"按角色区分初始工厂"的情况才需要配置。

> ⚠️ 多选过滤器下，若用户手动选中多个工厂同时查询，该组合未预热时会直接查数据库，速度较慢。此为用户主动操作触发，不影响初始加载性能。

---

## 五、预热数量

```
预热任务数 = 角色工厂配置中的条目数 + 1（默认值）
```

**示例**（6个工厂，6个销售角色，1个默认值；**多选模式**下额外加1个总经理角色）：

```
【单选模式】
惠州厂销售  → 预热 1 份
明阳厂销售  → 预热 1 份
南宁厂销售  → 预热 1 份
百色厂销售  → 预热 1 份
钦州厂销售  → 预热 1 份
池州厂销售  → 预热 1 份
默认值      → 预热 1 份
──────────────────
共 7 份预热（含多工厂角色用户，均命中上述条目）

【多选模式，需额外配置总经理角色】
以上 7 份 + 总经理角色（全部工厂）→ 共 8 份预热
```

预热数量与用户数量无关，完全由配置条目数决定，可控。

## 六、多角色用户的处理逻辑

当用户同时拥有多个角色时：

**情况A：只有一个角色在"角色工厂配置"中有配置**
```
用户角色：[惠州厂销售, 数据查看者, 财务经理]
有效角色：惠州厂销售（其余角色未配置工厂）
结果：显示并查询"惠州厂"数据  ✓
```

**情况B：多个角色都在配置中（过滤器为单选）**
```
用户角色：[惠州厂销售, 明阳厂销售]
初始显示：惠州厂（第一个匹配角色）← 命中惠州厂销售预热缓存 ✓ 速度快
选项列表：[惠州厂, 明阳厂]        ← 用户可手动切换查看
切换到明阳厂：                    ← 命中明阳厂销售预热缓存 ✓ 同样快
```

**情况C：用户无匹配角色**
```
用户角色：[数据查看者, 财务经理]（均未在角色工厂配置中配置）
初始查询：使用"过滤器默认值" ← 命中默认值预热缓存
选项列表：显示全部工厂（无限制）← 用户可以切换查看任意工厂
```

> 这也适用于管理员：若未配置工厂角色，默认可见全部工厂，符合"无限制 = 看所有"的语义。

## 七、风险与注意事项

### 风险1：多选模式下未配置的多工厂组合首次访问较慢

仅适用于**多选过滤器**。若某个角色需要同时查看多个工厂，但未在"角色工厂配置"中显式添加该组合，则首次访问会直接查数据库。

- **影响**：首次打开略慢（查数据库），查询结果会被自动缓存，后续访问正常
- **缓解方案**：在"角色工厂配置"中为该角色显式添加多工厂条目并纳入预热

> 单选过滤器下**不存在此风险**：每次只查一个工厂，所有单工厂组合均已预热覆盖。

### 风险2：配置遗漏导致体验不一致

若仪表盘"角色工厂配置"中某个角色未配置，该角色的用户会看到默认值，可能不符合预期。

- **建议**：上线前核对所有需要控制权限的角色是否都有对应配置

### 风险3：缓存过期或失效

- 预热缓存有有效期，过期后首次访问会重新查询
- 数据更新后缓存可能存在短暂的数据不一致

## 八、需要客户确认的决策点

在推进实现前，需要明确以下几点：

- [ ] **Q1**：仪表盘的工厂过滤器是多选还是单选？
- [ ] **Q2**：总经理/管理层是否已有对应的系统角色？若已有，直接在角色工厂配置中添加即可
- [ ] **Q3**：过滤器的"默认值"应配置为什么？（空、全部工厂、还是某个特定工厂）
